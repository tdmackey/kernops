# kernops

A kernel pipeline: upstream stable `linux-7.3.y` plus vendor patches (Ubuntu,
NVIDIA, GCP, AWS, Azure, our own), built as Ubuntu packages for noble (24.04)
and resolute (26.04), amd64 and arm64. Two older lines (`hwe-7.0`, `hwe-6.17`)
sit on Canonical's kernels.

Read first: `docs/workflows.md` (procedures), `docs/design-7.3-lts.md` (why).
`docs/backporting.md` covers resolving a conflict.

## Map

| Path | What |
|---|---|
| `kernel/sources.toml` | every tree we read patches from, and its patch-number band |
| `kernel/identity.toml` | product name, architectures, version scheme, per-series build switches |
| `kernel/lines/<line>/` | one kernel line: `line.toml` (base tag), `ledger/` (a decision per vendor commit), `series` + `patches/` (generated), `config/` |
| `tools/kpm/` | the patch manager; run it as `./scripts/kpm` |
| `scripts/build-line.sh` | build a line for a series; `scripts/in-builder.sh <series> …` runs anything in that series' container |
| `userspace/` | kernel-coupled userspace backports: `matrix.tsv`, `sources.lock`, per-package overlays |
| `modules/` | out-of-tree module pins |

## Commands

```sh
./scripts/kpm updates                    # what moved upstream (exit 10 = something did)
./scripts/kpm --line 7.3-lts status      # decisions per source
./scripts/kpm --line 7.3-lts verify --strict   # the gate
make check                               # static checks and tests
```

`--json` goes before the command name. Exit 3 from `import`/`rebase` means a
conflict that needs judgment.

## Rules

- `series` and `patches/` are generated by `kpm export`. Never edit them by
  hand; change the workbench branch or the ledger.
- Every ledger row needs a decision with a reason. Never accept a subject-only
  match (a "proposal") without reading both diffs.
- Before carrying a patch from a tree on an older base, check that upstream did
  not solve the same problem another way. If it did, the patch is `superseded`,
  not carried. See the `forward-port` skill.
- The kernel tree and patch series are identical for every Ubuntu series. Only
  packaging switches (`identity.toml` `[rules.<series>]`) and userspace differ.
- Never add `Signed-off-by`. Record what you changed in a `Conflicts:` note.
- Done means `kpm verify --strict` passes and the build does. Say which of
  compile, boot and hardware test actually happened.

## Environment

- Kernel work needs Linux on a case-sensitive filesystem: `WORK_ROOT`
  (default `~/kernops`) holds the unified git repo, build trees and outputs.
  The repo checkout itself may be on a Windows drive.
- Build a series in its container: `./scripts/in-builder.sh noble ./scripts/build-line.sh 7.3-lts noble`.
- Build order for a new series: `dwarves` (pahole) → kernel → the rest of
  userspace. bpfcc and bpftrace take bpftool and kernel headers from the kernel
  build.

## Things that have gone wrong

- Editing a script or `userspace/matrix.tsv` while a build that reads it is
  running: bash reads scripts as it goes. Wait for the build.
- Running git from inside a checkout on a Windows mount under WSL: worktree
  metadata holds a Windows path. kpm passes `-C`; do the same.
- `wsl.exe -- bash -c '… $VAR …'` expands `$VAR` in the calling shell. Write a
  script file and run that.
- A build under fakeroot is about five times slower; the packaging does not
  need it.
- Default git fetch negotiation against Launchpad can stall for an hour; kpm
  limits what it offers. Do not fetch the big trees by hand.
- A backport that "builds in seconds" probably built a metapackage. Look at
  what the .deb contains.
